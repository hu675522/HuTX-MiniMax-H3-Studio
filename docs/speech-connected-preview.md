# 已采用口播的 Local 预览链路修复

2026-09-13，保留当前 0.3.1 开发预览版本。

根因：采用只保存 Speech 节点的 adopted_audio_file 快照；Local 的音频卡片、@ 菜单和优化请求只读手动上传 media。后端 Queue 已支持 driver_audio 桥接，但执行前前端看不到该音频。选择 Hybrid 槽位不等于 AUDIO 接线。

使用：生成并采用口播，将 GHSpeechInputGH 的 audio 直接连接 GHLocalVideoInputGH 的 driver_audio，确认模型家族和槽位/冲突策略。在 Prompt 输入 @，选择“已采用口播”。首帧/首尾帧插入 <Audio 1>；全能参考按现有视频原声与独立音频顺序编号。示例：`<Picture 1> 中的人物按照 <Audio 1> 的口播说话，嘴型跟随声音。`

实现：新增只读 adopted-preview 查询，校验快照及 WAV 内容哈希，仅返回音频相对文件名和时长。执行时仍必须校验当前参数指纹。Local 在内存投影连接的已采用音频，复用现有标签规则；卡片只读，不提供无效裁切/删除。手动及自动优化共用该投影。投影不写入 gh_local_state_json、上传槽位或 node.properties，避免 Queue 重复媒体冲突。采用失效、断线、修改参数会刷新；已有 Prompt 不静默改标签。未采用/未接线/模型或槽位冲突有明确提示。

仅预览直接连接的 Speech 音频输出。其他 AUDIO 上游（例如裁切节点）必须执行后确定内容，当前显示说明，不冒充原始快照。原音频驱动、锁源、预算及 Fal/凭证 contract 不变。此次不重新验证模型口型质量。

## 模式与口播面板联动

按实机反馈，将口播折叠面板移动到模式按钮下方、Prompt tabs 上方，增加统一边框与内距。文本/首尾帧仅可确认 FL2VA、仅显示 Hybrid 音频；全能参考仅可确认 Ref2VA、仅显示参考音频槽 1/2/3。用户切换模式时，清除不适用的家族确认，等待重新确认，不自动替换实际主模型文件；已知官方模型家族不匹配时显示黄色提示。

旧工作流 auto 槽位仍按原后端自动追加规则运行，UI 显示其当前定位，手动选择后才固定槽位。槽位已满时要求明确选择替换对象，不自动填洞或重排音频编号。旧工作流保存的冲突配置显示待确认，不在加载时静默修改。

## 参考模式预览与口播界面精简

全能参考未添加画面时，原投影函数提前拒绝整个音频预览，导致已采用口播无法在参考槽显示。现仅在 UI 预览时允许缺失画面，显示已采用音频并提示添加图片或视频；优化准备仍调用严格校验，后端生成校验不变。没有修改音频编号、锁源、冲突或时长规则。

删除参考录音卡片底部说明段落。Mock 开关移入底部默认折叠的“开发调试”；已开启的旧工作流会明确标注并展开，保持测试模式可见且不自动转为真实生成。生成音频改为带“生成结果 / 已采用”标题的独立卡片，下载按钮位于标题右侧，播放器统一间距。
