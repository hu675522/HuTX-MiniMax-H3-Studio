## 产品结构

路径一保持：上传成品口播 → 原有锁音频视频流程。

新增路径：

1. 参考声线：参考音频 + 参考录音原文（本地标准零样本路径）+ 新台词。
2. 预设音色：选择受当前执行端支持的音色 + 新台词。
3. 用户明确选择本地或云端，不通过 Prompt 猜测，不自动跨端上传录音或触发付费。
4. 生成新口播 → 试听/保存/重生成 → 采用新音频 → 目标视频能力与时长检查 → 复用现有音频锁定流程。

新台词与视频画面 Prompt 分开。克隆参考录音只用于声音生成，视频阶段锁定的是新口播。独立 TTS 允许较长音频，单段视频限制在接入层执行。首版不做自动切段、拼接、自动精简台词或强制变速。

## 第一阶段：能力审计与接入设计

交付一张可追溯到代码/模型文档的能力表，按 local/fal、I2V/FL2V/Ref2VA、具体模型区分：

- 是否接受音频；是声音参考、原音频驱动还是仅最终混音；是否能够复用锁音频能力。
- 时长上下限、整数约束、帧数规则和尾部补齐策略。
- 首尾帧约束与音频输入是否能同时成立。

已核实：fal_router.py 当前要求 5～15 秒整秒；local_video_nodes.py 当前界面/校验允许 2～30 秒，并固定 lock_source。界面允许不代表每个本地 checkpoint 均支持整个范围；需要继续核验。用户当前 15 秒 Ref2VA 场景作为验收目标，不能反推所有模型上限。

旧节点以文件槽位接入音频，尚无可直接假定存在的 AUDIO 接口。先选择低风险的独立音频桥接节点或向新 Local UI 增加可选接入，默认未连接时行为完全一致。不得偷偷改动旧节点 required inputs、输出顺序或媒体编号。

退出条件：每个开放的视频模式都有明确的能力依据；不支持的组合在 UI 中禁用并说明原因，不能用简单混音冒充音频驱动。

## 第二阶段：独立口播节点与 mock 实现

建议模块：speech_nodes.py、speech_service.py、speech_validation.py、speech_providers/、web/js/speech_input.js；最终名称随仓库规范确认。

- 输出标准 ComfyUI AUDIO、实际时长和不含凭证的执行报告。命名与类型在实现前固定，不改变现有 Cloud/Fal 输出。
- 输入：执行端、克隆/预设方式、参考音频、参考原文、新台词、当前执行端实际支持的音色与语速参数。
- 状态：idle/running/success/error/cancelled；统一计时、重复请求保护、取消、清晰错误与试听。
- 试听或切换标签不调用服务；显式生成或工作流执行才运行 TTS。视频重试复用已采用的音频。
- 缓存按音频内容、文本、模型版本、音色及生成参数区分；不含 Key，不以 filename 充当音频身份。音频变化立即使旧结果标记过期。
- 预设音色按执行端过滤，支持示例试听；本地与云端 ID 不混用，不将 API 音色 ID 当作本地音色文件。

退出条件：全部 UI 与业务分支可通过 mock 验证，不下载模型、不调用付费 API。

## 第三阶段：本地声音克隆与预设音色

首选官方 CosyVoice 实现，模型 Fun-CosyVoice3-0.5B-2512。固定经过验证的代码提交和模型版本，不跟随 main 自动升级。

- 使用独立 Python 环境及仅监听 loopback 的 worker，不修改 ComfyUI embedded Python、Torch 或 H3 依赖；不强制安装训练/vLLM/TensorRT 功能。
- 先核验 Windows 推理依赖、模型与依赖许可，再给出实际下载大小和环境安装清单。
- 标准零样本路径提供参考原文；首版允许手工输入。自动转写是独立可选扩展，不默认增加 ASR 大模型依赖。
- 本地预设音色使用许可明确的参考音频/原文资源或用户自建音色；没有明确授权的声音样本不随包分发。
- TTS 与 H3 串行调度，TTS 完成后卸载或退出 worker 释放 GPU 资源。验证取消、失败与进程崩溃的资源回收。
- 验证参考音频格式、有效人声、采样率与空音频；必要的重采样属于 TTS 输入适配，不改 H3 音频合同。

退出条件：目标 Windows/RTX 4070 实测生成与释放显存通过；声音相似度、中文台词完整性由试听与转写检查共同验收，不能承诺零错字。

## 第四阶段：国内云端适配

首选阿里云百炼北京地域 CosyVoice；克隆候选 v3.5 Plus/Flash。预设配音按官方实际支持的系统音色模型单独选择，不能假定克隆专用模型自带系统音色。

- 固定地域、业务空间与服务端点；声音注册与合成的目标模型匹配，voice ID 不跨模型复用。
- 参考音频上传只使用服务商正式支持的方式；如果需要对象存储，明确访问期限与清理，不使用未经确认的公开图床或第三方上传中转。
- 新增语音服务凭证边界；可以复用安全存储组件，但不改变既有 Prompt Optimizer/Fal resolver、优先级或 DPAPI 格式，不自动取用优化器内存 Key。
- API Key 不进入 workflow、state、node properties、浏览器存储、音频 metadata、报告或日志。所有 provider 异常经过脱敏。
- 注册失败、合成超时、取消、限流、voice ID 失效、权限或地域错误均有明确反馈。付费请求重试须防止不确定结果导致重复计费。
- 国内网络优先使用官方北京服务，不宣称未经实测的绝对最快。首轮全 mock，实际联网时再测注册、合成和音频下载总耗时。

退出条件：mock API/凭证测试全通过；真实计费验收另行获得授权后执行，不在开发测试中消耗 credits。

## 第五阶段：视频时长检查与集成

2026-09-12 已完成 Local AUDIO 桥接、采用快照与自动化验证，详见 [第五阶段说明](speech-stage-five.md)。真实 H3 视频口型验收和正式打包部署仍归第六阶段；本轮不将 mock 波形锁定测试宣称为实机口型通过。

- 输入时仅提示预估时长，不以字数作为通过条件。
- 生成后以 waveform sample count / sample rate 得到实际时长，拒绝无效采样率、空音频、非有限数值等输入。
- 结合目标后端的整秒与帧数要求向上匹配能覆盖口播的有效视频长度；若对齐后越过上限则拒绝，不能为凑上限削掉台词。
- 用户主动选取音频片段时，检查被明确选中的片段时长；禁止隐式截断。
- 失败保留音频；提示具体模式、音频长度及允许范围。用户自行精简台词或调整语速再生成。
- 首尾帧、原有媒体槽位、canonical tags、GHVideoRequest、NormalizedVideoRequest、Fal endpoint/pricing/router、model_variant、输出顺序全部保留。

退出条件：旧路径不接新节点时通过原回归，新路径只锁定采用的新音频；无静默截断、无错误音频源选择。
